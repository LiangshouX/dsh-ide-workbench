# 代码智能（代码提示 + Usage / 跳转定义）可行性评估

> 状态：**评估稿**（2026-10-31）— 尚未开工，供产品/技术拍板
> 范围：`dsh-ide-workbench` 内置 CodeMirror 6 编辑器的两块能力
> 目标能力：① IDE 式代码提示（completion）② Usage 查看与代码跟踪（find usages / go to definition / Ctrl+点击跳转）

---

## 0. 结论（先看这段）

**能做，而且比预期便宜——但"便宜"的前提是走 LSP，并且接受"语言服务器由用户或 npm 提供"这个前提。**

| 结论 | 说明 |
|---|---|
| **两个功能一次性都做对，只有 LSP 一条路** | LSP 同时给出语义补全、跳转定义、查找引用、悬停文档、重命名。CodeGraph / 文本搜索都只能覆盖其中一半。 |
| **浏览器端几乎不用自己写** | 官方 `@codemirror/lsp-client@6.3.0`（MIT）已实现补全、跳转定义、**查找引用 + 引用面板**、悬停、签名帮助、重命名、诊断，并留了 `Transport` 与 `Workspace` 两个接缝，正好接本插件现有的 host/client 架构。**不要自己写 CM6 的 LSP 客户端。** |
| **host 端要自己写一个 LSP 管理器** | 镜像里没有现成的"语言服务器管理器"（`lsp-manager` / `@theia/lsp` / `@vscode/lsp-server-manager` 等均为 404），需自己实现进程生命周期 + stdio JSON-RPC + 文档同步 + 语言注册表。约 600–900 行。 |
| **成本量级** | LSP 主路径 **≈ 11–15 人天**；若再加"零配置兜底"（内置补全 / 代码图）**≈ 14–19 人天**。人天为本人估算，误差带 ±50%，不含跨平台验证与文档。 |
| **最大风险不是代码，是"用户没装语言服务器"** | TS/JS 与 Python 可做成 npm 依赖做到零配置；Java / Go / Rust / C++ 必须依赖用户的 JDK / Go / Rust / LLVM 工具链（Zed、VS Code 也是这么做的）。 |
| **性能：不是否决项，但要补一层防护** | 实测语言服务器稳态 0.8–2.2 GB，中心依赖型大项目冲到 **4.2 GB 后 OOM 崩溃**；宿主主线程阻塞 412 ms（worker_thread 隔离后 8 ms）。**约 2 人天**的防护层是必须的。详见 `docs/代码智能-性能开销评估.md`。 |
| **本项目历史上已明确推迟过这件事** | PRD-v2 第 12 章把"语言服务类能力（补全 / 检查 / Find Usages 语义版）"列为范围外，13.1 决策 #6 把 Find Usages 定为"文本搜索并标注「文本匹配」"。本次评估相当于**重新打开那个决策**。 |

**推荐路线**：分三阶段交付，LSP 为主干，把"零配置兜底"做成降级路径而不是另一套实现。

```
阶段 1（1–2 人天）  内置补全兜底（CM6 原生，零新依赖）
        ↓
阶段 2（11–15 人天） LSP 主干：host 管理器 + @codemirror/lsp-client + TS/JS & Python 零配置
        ↓
阶段 3（可选 2–4 人天） 无语言服务器时的符号级兜底（代码图 / 文本搜索）
```

## 2. 三条技术路线

### 路线 A：LSP（语言服务器协议）— 真 IDE 语义

宿主拉起真正的语言服务器（tsserver / Pyright / jdt.ls / gopls / rust-analyzer / clangd），按 LSP 协议收发；浏览器只负责渲染。

- ✅ 补全是**类型感知**的：能给出成员、方法签名、继承链、导入建议
- ✅ 跳转定义对**局部变量、参数、字段、重载**都准
- ✅ 查找引用是**语义引用**，不是同名文本
- ✅ 顺带白送：悬停文档、签名帮助、重命名、格式化、实时诊断（红波浪线）
- ✅ 生态标准，语言服务器由社区维护，本项目不背解析器的维护成本
- ⚠️ 依赖外部进程：用户可能没装语言服务器（Java 还要 JDK 21+）
- ⚠️ 宿主要自己写 LSP 管理器（镜像里没有现成的）
- ⚠️ 首次索引慢（tsserver 冷启动几秒到几十秒），需要"正在索引…"的状态反馈

### 路线 B：代码图索引（tree-sitter → 符号图）

用 tree-sitter 解析全仓库，建立"符号 → 定义位置"和"符号 → 引用位置"的图。

- ✅ **零配置**：20+ 语言（TS/JS/Java/Python/Go/Rust/C#/C/C++/PHP/Ruby…）开箱即用，不需要用户装任何东西
- ✅ 离线、纯本地、无外部服务
- ✅ 位置精确到 `file:line:column`
- ✅ 天然适合"项目符号搜索"（类名/函数名前缀补全）
- ⚠️ **不索引局部变量 / 参数 / 字段**（实测：本仓库 1038 个符号里 `variable` 只有 5 个）
- ⚠️ 没有类型感知：同名重载、遮蔽（shadowing）分不清
- ⚠️ 索引新鲜度是硬要求（实测见附录 A.3，陈旧索引会让行号整体偏移）
- ⚠️ 可用的现成实现 `@colbymchenry/codegraph` **平台包 265 MB**（含自带 Node 运行时 + tree-sitter 语法包）

### 路线 C：文本 / 词法近似

复用已有的 `fs.search`（git grep）按标识符全文匹配；同文件跳转用 CodeMirror 自带的语法树近似。

- ✅ **零新增依赖**，1 人天量级
- ✅ 同文件内的定义跳转可以做得挺准（Lezer 语法树有作用域信息）
- ❌ 跨文件只能靠"同名匹配"猜：分不清 `UserService`（类）和 `UserService`（变量）、分不清同名不同作用域
- ❌ 结果里混入注释、字符串、同名但无关的符号
- ❌ IDEA 用户一眼就能看出"这不是真 usages"

### 路线对比

| 维度 | A: LSP | B: 代码图 | C: 文本近似 |
|---|---|---|---|
| 语义补全 | ✅ 类型感知 | ❌ 只有符号名 | ⚠️ 词/关键字 |
| 跳转定义（类/函数） | ✅ | ✅ | ⚠️ 猜 |
| 跳转定义（局部变量/字段） | ✅ | ❌ | ⚠️ 仅同文件近似 |
| 查找引用（语义） | ✅ | ✅ 符号级 | ❌ 文本级 |
| 用户需要装东西 | ⚠️ 视语言而定 | ❌ 不需要 | ❌ 不需要 |
| 打包体积 | 视选择：npm 依赖 ~30–70 MB | ⚠️ 265 MB | ✅ 0 |
| 宿主工作量 | 600–900 行 LSP 管理器 | 300–500 行封装 + watcher | 100–200 行 |
| 维护成本 | 低（服务器社区维护） | 中（依赖第三方大项目） | 低 |
| 覆盖语言 | 取决于可用服务器 | 20+ | 全部（但精度低） |

**结论：A 与 B 互补，不是二选一。** A 是主干，B/C 是"用户没装服务器"时的降级。

## 5. 功能二：Usage 查看与代码跟踪

### 5.1 三个可交付层级

| 层级 | 做法 | 用户看到什么 | 成本 |
|---|---|---|---|
| **L0 文本级 Find Usages** | 复用 `fs.search`（git grep）+ 词边界匹配，结果标注「文本匹配」 | 能列出所有同名出现的位置；点进去能跳行 | **1 人天**（`src/host/search.js` 现成） |
| **L1 符号级跳转/引用** | 代码图索引（`findUsages` → 精确 `file:line:col`） | 类 / 函数 / 方法 / 常量 / import 的**真**定义与引用位置 | **3–4 人天** + 265 MB 依赖 |
| **L2 语义级 Usage 面板** | LSP `textDocument/references` + `findReferences` 面板 | 局部变量、字段、重载都准；按文件分组；支持"预览引用" | 含在主线成本内 |

### 5.2 L2 的现成程度（好消息）

`@codemirror/lsp-client` **已经实现了引用面板**：

- `findReferences`（默认 `Shift+F12`）+ `closeReferencePanel` + `findReferencesKeymap`
- 面板由库直接渲染，只需主题化（`.cm-lsp-*` 样式）
- `Workspace.displayFile(uri)` 是官方留给宿主实现的接缝 —— 正好用来"打开工作台自己的标签页并定位到行"

IDEA 的快捷键位可以在本插件侧映射：`Alt+F7` = Find Usages（PRD-v2 已预留）、`Ctrl+Click` / `F12` = 跳转定义（`@codemirror/lsp-client` 默认 F12）。

### 5.3 成本拆解（LSP 主干）

### 5.4 三个必须提前想清楚的技术点

**① 未保存草稿（dirty buffer）**
工作台的编辑器内容是 `tab.draft`（未保存），磁盘内容是 `tab.payload.content`（`EditorArea.jsx:128-133`）。LSP 若只看到磁盘内容，用户刚敲的变量就查不到定义。`@codemirror/lsp-client` 的 `Workspace.syncFiles()` 正是为此设计的抽象：把每个打开文件的"上次同步内容 → 当前内容"作为 `ChangeSet` 上报。**必须实现自定义 `Workspace`**，用默认实现会退化成只看磁盘。

**② 位置漂移**
请求发出后用户继续打字，服务端返回的位置会过期。库提供了 `workspaceMapping()` / `withMapping()` 做位置映射，**必须用**，否则"查找引用"点进去会跳错行。

**③ 索引新鲜度（代码图路线特有）**
见附录 A.3：实测陈旧索引会让行号整体偏移 26 行。这条只影响 L1（代码图），不影响 LSP。

### 5.5 收益评估

- **收益**：这是 IDEA 用户日常最高频的两个动作（Ctrl+点击看定义、Alt+F7 看谁在用）。做出来后，本插件从"带编辑器的 Git 面板"变成"能读代码的 IDE"，与 PRD-v2 里"JetBrains 式工作台"的定位一致。
- **风险**：若语言服务器缺失，用户看到的是一个"点了没反应"的按钮，**比没有这个按钮更糟**。所以"未安装"必须是一个**明确的、可操作的提示**，而不是静默失败。

## 7. 风险清单

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **用户没装语言服务器** → 功能形同虚设 | 🔴 高 | TS/JS + Python 做成 npm 依赖零配置；其余做 PATH 探测 + "未安装"引导页；所有入口都带明确状态 |
| R2 | **Windows 进程管理**：LSP 服务器的 stdout 是 JSON-RPC 帧，stderr 是日志，二者必须分离；部分服务器在含中文/空格的路径下会崩 | 🔴 高 | 沿用现有 git 的 argv 数组 spawn 做法；stderr 单独落盘；路径转 URI 时统一 `file:///C:/...` 编码 |
| R3 | **打包体积**：离线 tarball 由 `bundleDependencies` 决定（当前只有 `ws`），加语言服务器会显著变大 | 🟡 中 | 语言服务器设为可选依赖，不进 `bundleDependencies`；或只打包 TS 一个 |
| R4 | **XSS**：LSP 服务器返回的 Markdown/HTML 会渲染进页面 | 🟡 中 | 必传 `sanitizeHTML`；这是库内建选项，成本很低但**不能忘** |
| R5 | **内存**：⚠️ 实测比预期严重 —— tsserver 稳态 0.8–2.2 GB，3,120 文件的中心依赖型项目冲到 **4.2 GB 后 OOM 崩溃**（exit 134）；JDT LS 的 JVM 开销是已知的 GB 级 | 🔴 高 | **必须设死 `maxTsServerMemory`**（否则整机换页）；空闲自动退出；崩溃自动恢复 + 明确提示。详见 `docs/代码智能-性能开销评估.md` |
| R6 | **首次索引慢**：tsserver 冷启动几秒到几十秒，补全"像是没反应" | 🟡 中 | 状态栏显示"索引中"；补全弹窗在就绪前不空等 |
| R7 | **代码图体积 265 MB + 索引陈旧** | 🟡 中 | 阶段 3 做成可选；引入前必须解决"查询前同步"与"未保存草稿"两个正确性问题 |
| R8 | **DSH 侧无先例**：DSH 宿主没有插件跑过长驻子进程协议服务 | 🟢 低 | 宿主已经在跑 git 子进程与 PTY 终端，模式上有先例 |
| R9 | **快捷键冲突**：`F12` / `Ctrl+Click` / `Alt+F7` 在浏览器与 Electron 宿主中的行为 | 🟢 低 | 现有 `editorKeymap` 已有"浏览器保留键"处理经验（见 `CodeEditor.jsx:110-118` 注释） |

## 附录 A：实测证据

### A.1 官方 `@codemirror/lsp-client` 导出的能力（v6.3.0 实读 `dist/index.d.ts`）

`serverCompletion` / `serverCompletionSource` / `hoverTooltips` / `signatureHelp` / `showSignatureHelp` / `renameSymbol` / `formatDocument` / **`jumpToDefinition`** / `jumpToDeclaration` / `jumpToTypeDefinition` / `jumpToImplementation` / **`findReferences`** / `closeReferencePanel` / `serverDiagnostics` / `languageServerExtensions` / `LSPClient` / `LSPPlugin` / `Workspace` / `WorkspaceMapping`。

两个关键接缝：

- `Transport = { send(msg: string), subscribe(h), unsubscribe(h) }` —— 纯字符串 JSON，宿主做代理时浏览器不需要知道 LSP 帧格式。
- `abstract class Workspace` —— 需宿主实现 `openFile` / `syncFiles` / `displayFile` / `updateFile` / `closeFile`，正是本插件"标签页 + 草稿"模型的落点。

安全相关：`LSPClientConfig.sanitizeHTML` 存在（默认无），**必须提供**。

### A.2 代码图（`@colbymchenry/codegraph@1.6.2`）在本仓库的实测

```

findUsages(id) → 3 sites
```

DB schema（`.codegraph/codegraph.db`）证实其数据结构满足本需求：

- `nodes`：`kind, name, qualified_name, file_path, start_line, start_column, end_line, end_column, signature, docstring…` → **定义位置**
- `edges`：`source, target, kind, line, col, metadata, provenance` → **引用位置**（`calls / contains / imports / references / instantiates`）
- `unresolved_refs`：`from_node_id, reference_name, reference_kind, line, col, candidates, status` → 未能解析的引用

### A.3 索引陈旧会导致行号整体偏移（代码图路线的必修项）

实测 `findUsages` 返回 `EditorArea.jsx:105:31`，但该行实际内容与 `CodeEditor` 无关（真实引用在 11 / 131 / 173 行）。核对 DB：

| | 值 |
|---|---|
| 索引记录的 `EditorArea.jsx` 大小 | 27,497 字节 |
| 磁盘实际大小 | 35,938 字节 |
| 索引记录的 mtime | 1792855208950（早） |
| 磁盘实际 mtime | 1793418003056（晚） |

结论：**位置数据本身准确，错的是"索引没有跟上文件"**。任何基于代码图的方案都必须在查询前保证新鲜度（watcher 或查询前 sync），并处理未保存草稿。

### A.5 打包与发布的约束（实测 `package.json` / `.github/workflows/publish.yml`）
