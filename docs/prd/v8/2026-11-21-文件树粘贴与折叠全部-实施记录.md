## 1. 去向：一条规则，两个入口

之前键盘与右键菜单各算各的目标（`ProjectPanel.jsx` 里的 `pasteTarget` 与
`currentEntry?.isDir ? … : parentOf(…)`），两处可能给出不同的答案。
现在**只有一个地方**回答「往哪粘」——`src/client/tree-clipboard.js` 的
`pasteTargetOf(root, selected, menuEntry, focusedEntry)` [读码确认]：

| 情形 | 目标 |
|---|---|
| 选中了**一个文件夹** | **那个文件夹本身**（粘到它**里面**） |
| 选中了**一个文件** | 文件**所在的文件夹** |
| 选中**多个** | 它们**共同的父文件夹** |
| 什么都没选，右键点了一个条目 | 那个条目（文件夹→它自己，文件→它的父目录） |
| 什么都没选，也没开菜单 | **项目根目录** |
| 树搜索把选中行藏了 | **聚焦的路径**（树知道它是文件夹还是文件） |

面板只算一次（`pasteTarget`），菜单与键盘都用它（`runPaste(pasteTarget)`）——
**两处不可能再各说各话** [读码确认]。

「共同的父文件夹」是**按路径段**比的，不是 `startsWith`：
`C:\work\demo2` **不在** `C:\work\demo` 里面 [读码确认] `tree-clipboard.js:isUnder`。

### 1.1 拒绝对着干

- 文件夹不能粘到**它自己**里；
- 文件夹不能粘到**它自己的子文件夹**里（复制会走进自己，永远出不来）。

客户端**先**拒绝并给出人话，宿主**再**拒绝一次（纵深防御）[读码确认]。

### 1.2 让用户看见结果

粘贴之后：

- **目标文件夹被展开**、**新条目被选中** → 用户一眼看到它落在哪儿；
- 菜单的「粘贴」项**写明**了目标（`粘贴到 target-folder`）→ 粘贴**之前**就知道 [实测确认]。

## 2. 性能：一次粘 20 000 个文件时，插件不许卡

> 宿主半边跑在 **DSH 的宿主进程**里（`docs/prd/v8/2026-11-21-状态刷新事件化-性能审计.md` §1）：
> 宿主侧每一毫秒都是 DSH 自己的毫秒。

### 2.1 宿主：会呼吸的复制

原来的复制是 `fs.cp(source, dest, { recursive: true })`——一把梭，跑多久不知道，
也没法中途叫停。现在是 `src/host/fileops.js` 的 `copyTree()` [读码确认]：

| 做法 | 为什么 |
|---|---|
| **迭代**遍历（显式栈，不用递归） | 深的目录树不会爆栈 |
| 每 64 个条目 `setImmediate` **让出事件循环** | 宿主在被复制的同时**继续回答别的请求** |
| `copyFile`（流式） | 大文件不进内存 |
| **预算**（条目数 / 字节数） | 一次粘贴不会跑到天荒地老 |
| **信号**可中止 | 用户能喊停，宿主**真的停下来** |
| 符号链接**按链接复制** | 一个指向别处的链接不会把整棵目录树拖进复制里 |

预算的诚实性：**字节预算在写之前**检查（`lstat` 先拿大小），
所以**不会有半个文件**——半个文件比没有文件更糟 [读码确认] `fileops.js:copyTree`。
到顶了就**如实说**：`truncated: true` + 点名**哪些条目没复制**，
前端弹「复制没有完成 / 有 N 个条目没有复制」。

### 2.2 实测（2026-11-21，Windows，Node v22.22.2）

| 场景 | 结果 |
|---|---|
| 复制 3 000 个文件 | **1.35 s**；复制期间点工具栏按钮 **3 ms** 有响应 [实测确认] |
| 复制 20 000 个文件 | **44.2 s**；期间宿主回答其它请求：中位 **8 ms**、最差 **132 ms**（磁盘争用），**从不阻塞** [实测确认] |
| 20 000 个文件复制结果 | `truncated: false`，全部落盘 [实测确认] |
| 复制中点「取消」 | **52 ms** 内停下；宿主侧的复制**也停了**（2073 个文件后再等 4 s，仍然是 2073） [实测确认] |

### 2.3 客户端：别让界面假装没事发生

- 复制期间树上出现一条 **「正在复制…」+「取消」** 的细条 [实测确认]；
- 「取消」→ `store.cancelPaste()` → `AbortController` → `fetch` 的信号 →
  宿主 `fs.move` 的信号 → `copyTree` 停下 [读码确认]；
- 状态放在 **store**（`pasteBusy`），因为它是剪贴板的事实，不是面板的一瞬。

### 2.4 粘贴之后不做傻事

- **不重建**整个文件索引：只是**作废**它（`fileIndexRoot: ''`），
  下次搜索时再重建——没人要求搜索，大项目不该为一次没人要的扫描买单 [读码确认]；
- 只**重新列举**被碰到的几个目录，不全树刷新 [读码确认] `store.js:moveEntries`。

> `tests/fileops.test.mjs` 里的一条断言守着一个真 bug：
> `4 << 30` 在 JavaScript 里是 **0**（位移按 32 位算），字节预算会变成 0，
> **每一次粘贴都会被拒绝**。现在它写成 `4 * 1024 * 1024 * 1024`，并且有用例守着。

## 6. 没做的

- **不做**「粘贴时问冲突怎么处理」的对话框：沿用现有的**自动改名**
  （`name-copy`），和 JetBrains 的重复行为一致；
- **不做**断点续传：一次粘贴到顶就停，下一次粘贴从头再来（实测如此）。
  这是刻意的：留一个半截的目录树比重新拷一遍更让人困惑；
- 折叠只有「全部」，没有「展开到第 N 层」——那是另一个功能。
