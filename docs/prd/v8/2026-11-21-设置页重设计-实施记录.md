## 1. 改之前的诊断

这一轮的用户诉求是「**很难快速找到需要的设置**」。以下每一条都能复核到改动前的源码。

### 1.1 页面是**一条没有导航的长列**

| 设置页是**单列滚动**，只有一个纵向流 | `src/client/SettingsPanel.jsx:270-523`（`React.createElement('div', { className: 'iwb-settings' })` 里 9 个 `Group` 顺序排列） | [读码确认] |
| 容器宽度上限 720px，**没有任何分类导航** | `src/client/styles.js:1300-1310`（`.iwb-settings { max-width: 720px }`），全文无 `role="tablist"`、无搜索框 | [读码确认] |

### 1.2 **9 个真实生效的快捷键在设置页里根本不存在**

### 1.5 密度与容器宽度不匹配

| 事实 | 位置 | 标注 |
|---|---|---|
| 设置模态宽度 `min(620px, calc(100% - 40px))`，而它挂在 **DSH 右侧栏**（实测右侧栏 ≈522 px）→ 实际内容宽 **≈457 px** | `src/client/styles.js:1425`（改动前的模态宽度）+ 实测右侧栏宽度 | [读码确认] + [实测确认] |
| 行是 `min-height: 48px` 的**定高盒**，窄容器下换成 `flex-wrap` 的三段式 | `src/client/styles.js:1324-1327,1400-1405`（改动前） | [读码确认] |

> **结论**：在这个宽度里，VS Code 式**左右两栏**放不下（分类导航 ≈150 px + 内容 ≈300 px，控件会被压到不可用）。
> 因此本轮选择 **单列 + 顶部分类 tablist + 即时筛选**（见 §2），这是**被容器宽度决定的**，不是偏好。

### 2.3 交互模型

| 能力 | 做法 | 位置 |
|---|---|---|
| 即时筛选 | `<input type="search">` + `role="search"` 地把；索引只构建一次，按键只是**在字符串数组里过滤**，**不走异步** | `SettingsPanel.jsx:726-742` |
| 分类导航 | `role="tablist"` + `role="tab"`（`aria-selected` / `aria-controls` / roving `tabIndex`），面板是 `role="tabpanel"` | `SettingsPanel.jsx:762-790` |
| 分类切换 | 方向键 / Home / End 在 tablist 里走，**焦点跟随**；Tab 键照常离开（无陷阱） | `SettingsPanel.jsx:664-676` |
| 快捷键 | `/` 把光标放进筛选框（文本框里除外）；`Esc` 先清筛选、再离开输入框 | `SettingsPanel.jsx:678-706` |
| 命中计数 | 每个分类 chip 后面带命中数；`role="status" aria-live="polite"` 播报 | `SettingsPanel.jsx:743-747, 762` |

### 2.4 「诚实状态」

| 状态 | 表现 | 依据 |
|---|---|---|
| **已修改**（与默认值不同） | 徽标「已修改」+ 该行的「恢复默认值」按钮 | 与 `resetPatch()` 的默认值表比较 |
| **仅对新会话生效** | 徽标「仅对新会话生效」 | `terminal.shell` / `terminal.outputLimitBytes` 都在**会话建立时**被宿主读取（`src/index.js:933,958`） |
| **已在别处更改** | 徽标「已在别处更改」；宿主文档变了而草稿没变时标出 | 设置文档是真源 |
| **未能保存** | 该行左侧红色边线 + 徽标「未能保存」；页脚「保存失败」 | 写盘后比对**已发布**的文档：值没落进去 = 没保存成功 |
| **永久删除** | `delete.useRecycleBin` 关掉时徽标「永久删除」 | 破坏性选择单独成组并标出 |

### 2.5 视觉系统

- **行是 grid，不是定高盒**：高度随内容走，说明文字 `inline-size: min(100%, 65ch)`、无单位行高 → 窄宽/放大时不裁字（`styles.js` 的 `.iwb-settings-row` / `.iwb-settings-hint`）。
- **控件列统一**：宽容器里标签与控件同一行、说明另起一行；窄容器（≤560 px）控件落到标签下方。
- **令牌化**：页面只用 `var(--iwb-*)`；组件级令牌（`--iwb-settings-header-height` / `--iwb-settings-row-pad` / `--iwb-settings-read-measure`）由语义令牌搭出来，**页面不写任何色值**。
- **克制的用色**：徽标只用状态色（accent / warn / error），页面底色始终是主题色。
- **密度**：新增 `ui.density`（`comfortable` / `compact`）——行距与组距由 `--iwb-settings-row-pad` / `--iwb-settings-group-gap` 两个组件令牌控制。

## 3. 用工作区 Skill 做的设计决定

工作区里的技能（`D:\Code\Node\DSH-IDE-TOOLWINDOWS-ROOT\.agents\skills\`）是本轮设计的**方法来源**。逐条对应：

### 3.1 `ui-ux-pro-max`（`scripts/search.py`，数据集 `src/ui-ux-pro-max/data/*.csv`）

| 技能条目（出处） | 我的具体决定 |
|---|---|
| **Style: Minimalism & Swiss Style**（query `developer IDE settings panel dense minimal professional dark mode`，`--design-system --density 8 --variance 3 --motion 2`）：grid-based / essential / high contrast；Accessibility risk low，要求 contrast-text-4.5 / keyboard / visible-focus / reduced-motion | 行改成**两列 grid**（标签+控件），不用定高盒；页面靠网格与留白分层，不靠装饰。**没有**照抄该次输出的 Pattern（FAQ/文档落地页）——它落到文档站模板上了，与 IDE 设置面板无关；只保留了其中成立的「search bar prominent」 |
| **Density 8/10**（8–32 px 刻度、偏紧凑） | 行内边距 `--iwb-space-3`、组距 `--iwb-space-5`、chip 高度 24 px；分类条换行而不是被裁成一行 |
| **Motion 2/10**（只允许 hover/焦点过渡 150–300 ms） | 过渡只用 `--iwb-dur-fast`（120 ms）/`--iwb-ease`，只出现在 hover / focus / color；没有入场动画、没有滚动揭示 |
| **No Results（Search / Medium）**：`Show 'No results' with suggestions`，不要 `Blank screen or '0 results'` | 空状态说出**当前查询词** + 「换一个更短的关键词，或清除筛选后按分类浏览」+ 「清除筛选」按钮（`SettingsPanel.jsx:793-807`） |
| **Text Reflow and Spacing（Critical）**：`inline-size: min(100%, 65ch); height: auto; line-height: 1.5`，不要固定宽高裁字 | 说明文字 `--iwb-settings-read-measure: 65ch`；行高**内容驱动**（去掉 `min-height: 48px`）；行高用无单位值 |
| **Chip Collection Reflow（High）**：换行，不要 `height:32px;overflow:hidden` | 分类 chip 用 `flex-wrap: wrap`，没有固定高度、没有溢出裁剪 |
| **Focus States（High）**：每个可交互控件都要有可见焦点环，模态框内也算 | 筛选框、chip、行内控件、重置按钮全部有 `:focus-visible` 轮廓（`--iwb-accent`）；模态内同样有 |
| **Focus Not Obscured（Medium）**：粘性 UI 不许盖住焦点 | 粘性表头 + `scroll-margin-top: var(--iwb-settings-header-height)`（行与面板），焦点行永远露在表头下方 |
| **Keyboard Navigation（High）**：tab 顺序与视觉顺序一致，无键盘陷阱 | 分类条是标准 tablist（方向键 / Home / End、roving tabindex）；Tab 正常离开；面板 `tabIndex=-1`（它里面就是控件，不占一站） |
| **Form Labels / Input Labels（High）**：每个输入都要有**可见**关联标签，不能只靠 placeholder | 行标题从 `<div>` 改成 `<label for>`，控件拿到稳定 `id`（`iwb-settings-<key>`）；说明文字改成 `aria-describedby`（是描述，不是名字的一部分）。**快捷键 chip 不是表单控件**，用 `role="group" aria-labelledby` 由可见标题命名 |
| **Compact Label Overflow（High）**：徽标保持单行完整 | 徽标 `white-space: nowrap`；「恢复默认设置」按钮 `flex: 0 0 auto; white-space: nowrap`（实测发现它会折成两行，已修） |
| **Submit Feedback（High）**：保存要有 loading → success/error | 页脚「保存中… / 已保存 / 保存失败」三态 + `role="status"`；写盘失败时该行还有「未能保存」徽标 |
| **State contrast parity**：pressed/focused/disabled 在明暗两套主题都要能分辨 | 选中 chip 用 `--iwb-surface-selected`（accent 混合色）、焦点用 `--iwb-accent` 轮廓、禁用态用 `--iwb-muted`——都是**两套主题都成立**的语义令牌 |
| **Token-driven theming**：语义令牌，不硬编码 | 设置页样式里**零**色值（`settings-search.test.mjs` 的「the settings page does not name a colour of its own」用例守着） |

### 3.2 `design-system`（`SKILL.md`）

| 条目 | 我的具体决定 |
|---|---|
| **Three-Layer Structure**：Primitive → Semantic → Component | 新增的 `--iwb-settings-*` 是**组件层**令牌，全部由语义令牌搭出（`--iwb-space-*`、`--iwb-radius-*`、`--iwb-fg`、`--iwb-accent`…），页面自己不发明长度与颜色 |
| **Never use raw hex in components - always reference tokens** | 同上；设置页样式块内**没有**任何 hex（有用例守着） |

### 3.3 `frontend-design`（`SKILL.md`）

| 条目 | 我的具体决定 |
|---|---|
| 「Minimalism or refined minimalism needs **restraint, precision, and careful attention to spacing, typography, and subtle details**」 | 专业工具的工作面选**克制的极简**：网格 + 留白 + 一处状态色，不做装饰性动效 |
| 「Match implementation complexity to the aesthetic vision」 | 设置页不是落地页：没有 hero、没有滚动揭示、没有新字体依赖（仓库的 `tests/fonts.test.mjs` 守着字体授权，且离线产品不能拉 Google Fonts） |

> **与仓库规则冲突时以仓库规则为准**：技能给的 hex 调色板与 Google Fonts 一律**未采用**（只用 `--iwb-*` 令牌、不新增字体依赖、不新增 npm 依赖）。
