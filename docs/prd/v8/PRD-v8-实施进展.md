### 2.6 「液态玻璃」材质（借鉴用户提供的视觉参考）

参考图是近年的 **liquid glass**：半透明、顶部高光、背后模糊、宽而柔的投影。

**酌情采纳的部分**：这套材质落在**浮层**上 —— 菜单、对话框、提示、浮出层、预览工具条：

```css
@supports ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .iwb-menu, .iwb-modal, .iwb-toast, .iwb-outline, .iwb-html-actions {
    background: var(--iwb-glass);           /* 74% 不透明 */
    backdrop-filter: var(--iwb-glass-blur); /* saturate(180%) blur(20px) */
    box-shadow: var(--iwb-glass-edge), var(--iwb-glass-shadow);
  }
}
```

**没有采纳的部分**：密集表面（文件树、编辑器、各类条）**保持实心**。理由有二 ——
① 树后面加模糊会不可读；② 每行一次 `backdrop-filter` 会让滚动掉帧，而仓库的性能闸门不允许。
**用例守着这条界线**：`tests/workbench-chrome.test.mjs` 断言玻璃块里**只能**出现那五个浮层选择器。

> 浏览器不支持 `backdrop-filter` 时保留不透明表面 —— 效果是**加法**，不是依赖。

## 3. 方向 C —— 稳定性加固（§3）

> 这一节的**宿主半边**由一个子代理实施，主代理复核了 diff 并补上了设置页与用例。

### 3.1 终端输出封顶（TERM-01..06）

| 项 | 落点 |
|---|---|
| 上限 | `host/settings-store.js`：`DEFAULT_TERMINAL_OUTPUT_LIMIT = 8 MiB`；设置项 `terminal.outputLimitBytes` |
| 兜底 | `terminalOutputLimit(document)`：缺失 / 非数字 / ≤0 ⇒ 回落默认 |
| 计数 | `src/index.js` `attachTerminal`：按 **UTF-8 字节**（`Buffer.byteLength`）计，不按字符串长度 |
| 截断 | 到达上限 ⇒ **只发一次** `{type:'truncated', bytes, limit}`；之后的输出丢弃；**会话不死**（输入、resize、信号、退出帧都照常） |
| 边界 | `sliceUtf8()` 在 **UTF-8 字符边界**上切，不会切出半个字 |
| 客户端 | `TerminalPanel.jsx`：收到 `truncated` 帧 ⇒ 在终端里**打印一行可见提示**；xterm 的 `scrollback` 封顶 **5000 行** |
| 设置页 | `SettingsPanel.jsx` 新增一行「输出上限（MiB）」，中英双语 |

**实机验收**（`127.0.0.1:3081`）：把上限临时改成 64 KiB，开一个新终端会话，
`1..5000 | ForEach-Object { "y" * 100 }` ⇒ 终端里出现
`[output truncated after 65536 bytes]`（页面被 Chrome 自动翻译成中文），**会话仍然可用**。验收后上限已还原为 8 MiB。

### 3.2 PDF 走二进制（PDF-01..07）

| 项 | 落点 |
|---|---|
| `fs.read` | `host/workspace.js`：PDF **只回元信息**（`kind/mime/size/mtimeMs/path`），**不再有 `data`** |
| 二进制路由 | `src/index.js`：`GET /ide-workbench/raw?root=&path=` ⇒ `application/pdf` + `content-length` + `cache-control: no-store` + 原始字节 |
| 围栏 | 同一 `fence(req)`（403）+ `canonicalRoot`/`resolveInside`（越界 403）+ 非 PDF（400）+ 超限（413） |
| 客户端 | `api.js` `rawUrl()` → `store.rawUrl()` → `pdf-view.js` `fetchPdfBytes()` → `pdf-engine.js` `getDocument({data})` |
| 不驻留 | **store 里不留字节**，只在渲染进程里随文档活着 |

**实机验收**：`/ide-workbench/raw` 返回 **200 / `application/pdf` / 193 字节 / `%PDF-1.4` 开头**；
同一个文件的 `fs.read` 答案里 **没有 `data` 字段**；越界路径 **403**。

## 5. 图片预览的拖动（§6）

**根因**：`ImageViewer.jsx` 的 `onMove` 用的是**从拖动起点算起的累计位移**，却把它**加到当前的 pan 上** ——
pan 随移动次数**平方增长**，轻轻一拖就撞到钳位 ⇒ 「直接跳到最左边」。

**修法**：
1. `image-zoom.js` 新增 `beginDrag()` / `dragPan()`：拖动状态**持有起始时的 pan**，且**永不被覆盖**；
   `panFromDrag()` 是「起点 pan + 位移」的**绝对式**。
2. `ImageViewer.jsx`：拖动中**直接写 DOM 的 transform**（跟手），React 状态**每帧至多提交一次**（不卡）。

> ⚠️ **第一版修法自己也有这个 bug**：`drag.pan = pan` 把起点冲掉了。**实机拖动测出来之后才改对** ——
> 这正是「改动要能在真机上跑一遍」的道理。

**实机验收**：放大到 177% 后左键拖 4 步 × 10px ⇒ 平移依次 **-10 / -20 / -30 / -40**，**逐像素跟手**。

### 10.1 语法配色是**解**出来的，不是挑出来的

旧配色的病根不是「颜色不好看」，而是**两分支的混合比例**：
`80% 色相 + 20% 近黑`（亮）/ `52% 色相 + 48% 近白`（暗）—— 暗色分支里 48% 的近白把色相洗成了粉彩，
关键字成了灰紫、字符串成了灰橄榄。

做法：把 `tests/styles-theme.test.mjs` 的 **oklab 数学原样搬进一个求解器**，
色相按「性格」定，**明度与两个混合比例一起搜**：

| 令牌 | 色相 | 亮色 | 暗色 |
|---|---|---|---|
| comment | `#638392` | `#4d6571` | `#acbdc5` |
| string | `#259f56` | `#257946` | `#66b57d` |
| number | `#d07200` | `#9d591b` | `#dd975d` |
| keyword | `#a870e9` | `#7f58b0` | `#bb93ef` |
| type | `#0099a8` | `#187581` | `#63b2bd` |
| function | `#2a8ee7` | `#286daf` | `#65a9ee` |
| property | `#009b8f` | `#18766f` | `#63b4aa` |
| tag | `#e45c79` | `#ab4a5f` | `#ee8899` |
| heading | `#6684f4` | `#4f66b8` | `#87a2f8` |
| invalid | `#ee564a` | `#b3473e` | `#f78679` |

比例：亮色 **76% 色相 + 24% 近黑**，暗色 **74–76% 色相 + 24–26% 近白**（comment 50/50，它该退后）。

> **踩过的坑**：测试会把**每个分支放到每一个场景**里验（暗色分支 × 亮色前景 也是一种），
> 求解器第一版只验了「自己的主题」，于是 comment 在「暗色分支 × 亮色前景」下色相漂了 8.8°。
> 补上那三条交叉之后才有解。

**最差对比度 5.35:1**（测试要求 ≥ 5），`styles-theme.test.mjs` 15 条全绿。

### 10.2 字体：能白拿的都白拿

- **连字**：`font-variant-ligatures: contextual` —— Cascadia Code / JetBrains Mono 天然带
  programming ligature，`=>` `!=` `>=` 变成一个字符。实机截图里 `=>` 已经是连字。
- **光学尺寸**：`font-optical-sizing: auto` —— Segoe UI Variable 是带光学尺寸轴的可变字体。
- **等宽数字** + **抗锯齿**（上一轮做的）。

> **一个诚实的结论**：这台机器上只有 `Segoe UI Variable Text` / `Segoe UI` / `Cascadia Code` /
> `Consolas` / `Microsoft YaHei` —— **Inter 与 JetBrains Mono 都没装**。
> 所以字体的「现代感」不能指望换字族，只能靠**处理**（字重、字距、连字、光学尺寸）。

### 10.5 顶栏的分支 chip 不再像贴纸

### 10.6 Git 历史面板（子代理实施，主代理复核并补齐样式与文案）

| 问题 | 处置 |
|---|---|
| 「仅当前分支 / 所有分支」是**把自己的状态写在脸上的**文字按钮 | 改成分段控件：`当前分支 | 所有分支`，两个选项都写出来，`role="radiogroup"` + `aria-checked` 标出当前那个 |
| 六种控件挤在一条里 | 读作**两簇**：SCOPE（仓库 / 分支 / 分支范围）与 FILTERS（日期 / 作者 / 消息 / 路径），中间一道发丝分隔 |
| 没有「清除筛选」 | 有，且**只在有筛选时出现** |
| **切换分支延迟明显** | 根因：每次改筛选都跑一次 `git log` **子进程**。现在分支范围 / 作者 / 消息 / 日期全部改为**客户端过滤**（数据已在内存），**只有路径筛选留在服务端** |
| 「所有分支」可能显示成空历史 | 宿主的日志页同时取 `--all` 与 `HEAD` 两个窗口（去重），否则 tip 较旧的分支会显示为空 |

**实机量过**：切换分支范围 → `git.log` 请求 **0 次新增**；在消息框里打字 → **0 次新增**。

> **代价**：每次**载入**日志多一个 `git log` 子进程（不是每次筛选），一页最多 400 行；
> 客户端过滤是一次遍历（亚毫秒），面板仍然只渲染可见的那一屏。

### 10.7 Markdown 文档目录：点外面就关

以前唯一的出口是再点一次那个按钮 —— 读者得在一堆字里找回刚才点的那个角。
现在它是**浮层**：点它外面（页面空白、正文、别的控件）关闭，Escape 也关；
点**打开它的那个按钮**不算「外面」。

## 11. 第三轮 —— 字族随插件走、标记要清楚、仓库只切一次（§6.7）

> 触发：「Inter 和 JetBrains Mono 可以装」「Project 的这个图标有点太糊了」
> 「commit 历史里面有两个位置可以切换仓库，冗余的」。

### 11.1 两个字族**随插件走**

以前 `--iwb-font` 里写着 `"Inter"`，`--iwb-mono` 里写着 `"JetBrains Mono"` —— 只是**希望**机器上有它们。
实测这台机器上**两个都没有**（只有 Segoe UI Variable Text / Segoe UI / Cascadia Code / Consolas / Microsoft YaHei），
所以工作台一直是用 Windows 的默认字族在渲染 —— 这就是「字体平庸」的真正原因。

现在两个可变字族的**拉丁子集**随插件发布：

| 字族 | 文件 | 大小 | 轴 |
|---|---|---|---|
| Inter | `assets/fonts/inter-latin-opsz-normal.woff2` | 72.9 KB | `wght` + `opsz` |
| JetBrains Mono | `assets/fonts/jetbrains-mono-latin-wght-normal.woff2` | 40.4 KB | `wght` |

- **以 data URI 内联**（不 fetch）：插件不能指望宿主替它伺服静态文件，内联也没有第二次请求。
  构建产物因此多了 **147.8 KB**（客户端包 4925 KB → 5073 KB）。
- **注入发生在构建期**：`styles.js` 里是一个**注释占位符** `/*__DSH_FONT_CSS__*/`，
  `scripts/build-client.mjs` 把它换成真正的 `@font-face`。
  源码里因此**没有二进制导入** —— 每个测试套件都是用裸 esbuild 打包客户端的，
  `.woff2` 导入会要求每个套件都配一个 loader（第一版就踩了这个坑）。
- **Inter 带 `opsz` 轴**，所以 `font-optical-sizing: auto` 真的起作用：11px 的标签和 26px 的标题
  用同一张脸，却按各自的视觉尺寸画。
- 子集**只含拉丁**：中文继续回落到系统字族（读者本来就期待那样），CJK 字族要 megabytes 量级。
- **OFL-1.1**：两份许可证放在 `assets/fonts/`，并加进包的 `files`（字族进了产物，许可证就得跟着走）。

**实机验收**：`document.fonts` 里 `Inter 100 900` 与 `JetBrains Mono 100 800` 均为 **loaded** ✓。

### 11.2 Project 的标记重画（**先看清楚再改**）

上一版是「梳齿」：脊线 + 三条臂 + 三个方框。把它放大到 120px 才发现两件事：

1. 它在 20px 下**是一团糊** —— 六条细笔画挤在 20 个单位里；
2. 放大后它读作**一摞书**，不是文件树。

⇒ 重画成**最少的笔画**：一根脊线、两条臂、两个**实心**节点。
实心的点在任何尺寸下都是清楚的，几个像素的轮廓不是。描边同时由 1.8 降到 **1.55**
（1.8/20 是 9%，比同族图标的 1.35/16 = 8.4% 更重）。

> 只能靠眼睛看。

### 11.3 commit 历史：仓库只切一次

实机反馈：**两个地方都能切仓库**（底部 dock 的表头里一个，Git 窗口的筛选行里又一个），
而筛选行里的那个把**分支名挤成了两行**。

- 筛选行里的**仓库切换器删除**；dock 表头里那个**保留**（它是 dock 的表头）。
- 腾出来的位置**给分支**：`⑂ main ⌄` 现在占一行、等宽字、不折行。
- 「**还没有仓库**」的空状态**仍然**能选仓库 —— 表头的切换器在那种情况下帮不上忙，
  所以那个空状态里的按钮和它的浮层都留着。

**实机验收**：Git 窗口里 `.iwb-repo-switch` **0 个**，整个工作台 **1 个**（dock 表头）；
分支 chip 高 **24px**（一行）。

## 13. 文件树的粘贴与「折叠全部」（2026-11-21）

> 详细记录：`2026-11-21-文件树粘贴与折叠全部-实施记录.md`

### 13.1 折叠全部

工具栏（筛选文件 / 文件定位 / 刷新）后面多了一个**折叠全部**：树收成一层，视口回到顶部。
图标是新画的 `IconCollapseTree`（文件夹 + 向上的折角）——已有的 `IconCollapseAll`
画的是「藏起所有工具窗口」，不是树，语义不能混用。

### 13.2 粘贴的去向：只有一条规则

键盘与右键菜单以前**各算各的**目标，可能给出不同的答案。现在**只有一个地方**回答
「往哪粘」（`src/client/tree-clipboard.js` 的 `pasteTargetOf`）：

| 情形 | 目标 |
|---|---|
| 选中了**一个文件夹** | **那个文件夹本身**（粘到它里面） |
| 选中了**一个文件** | 文件所在的文件夹 |
| 选中**多个** | 它们共同的父文件夹（按路径段比，不是 `startsWith`） |
| 什么都没选 | 项目根目录 |

菜单的「粘贴」**写明**了目标（`粘贴到 target-folder`），粘贴之后**目标文件夹被展开、
新条目被选中** —— 用户不用去猜它落在哪儿。

文件夹不能粘到**它自己**里，也不能粘到**它自己的子文件夹**里：客户端先拒绝（并说人话），
宿主再拒绝一次。

### 13.3 一次粘 20 000 个文件，插件不许卡

宿主的复制从 `fs.cp` 换成了自己的 `copyTree()`：迭代遍历（不爆栈）、每 64 个条目
**让出事件循环**（宿主继续回答别的请求）、字节预算**在写之前**检查（不留半个文件）、
条目与字节都有预算、**信号可中止**、符号链接按链接复制。

实测（Windows / Node 22）：

| 场景 | 结果 |
|---|---|
| 复制 3 000 个文件 | 1.35 s；复制期间点工具栏 **3 ms** 有响应 |
| 复制 20 000 个文件 | 44.2 s；期间宿主回答其它请求中位 **8 ms**、最差 **132 ms**，**从不阻塞** |
| 复制中点「取消」 | **52 ms** 停下；**宿主侧的复制也停了**（2073 个文件后不再增长） |

客户端在复制期间显示「正在复制…」与「取消」，并把中止信号一路送到宿主。
粘贴之后**不重建**文件索引（只作废，下次搜索时再重建）——没人要求搜索，
大项目不该为一次没人要的扫描买单。

### 13.4 一个真 bug（被用例钉住）

字节预算写成 `4 << 30` —— JavaScript 的位移按 **32 位**算，`4 << 30` 是 **0**，
于是**每一次粘贴都会被拒绝**。现在写成 `4 * 1024 * 1024 * 1024`，并且有用例守着。
