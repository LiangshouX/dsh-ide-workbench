# PRD-v8 — 工作台入口归位与视觉精修 · 稳定性加固

> **版本**：v8
> **日期**：2026-11-21
> **对象**：`dsh-ide-workbench`（DSH 插件，IDE 工作台 core）
> **基线**：`feat(core)/issue-fixing-and-enhancement`（`9face89`）
> **分支**：`feat(core)/v8-entry-visual-and-stability`
> **性质**：本文件是本轮的**唯一规格**，实现以它为准；实施记录另写 `PRD-v8-实施进展.md`。

## 0. 摘要

本轮是一次**由真实使用反馈驱动的迭代**，四个方向：

| 方向 | 一句话 | 性质 |
|---|---|---|
| **A 入口归位** | 工作台在 DSH 左侧栏底部（头像上方）留下的那个入口**撤掉** | 减法 |
| **B 视觉精修** | 工作台整体**脱胎换骨**：字体、按钮、图标、层次感 | 增量（重做表现层） |
| **C 稳定性加固** | 终端输出无上限、PDF 整文件 base64 —— 两个会拖垮渲染进程的隐患 | 修复 |
| **D 交互收敛** | 冗余按钮清理、Alt+Insert 新建类型歧义 | 修复 + 收敛 |

> **一句话目标**：让工作台**看起来像一个成熟的产品**，而不是一个「能用」的插件；
> 同时保证它**永远不会把 DSH 拖垮**。

## 1. 方向 A —— 插件入口归位

### 1.1 现状

工作台在**三个**位置各留了一个入口（`packages/workbench/src/client/index.jsx`）：

| # | 插槽 | 位置 | 评价 |
|---|---|---|---|
| 1 | `conversation.session.header.utilities` | 会话标题右侧的图标簇 | ✅ 合理：工作台是这一轮的产物，入口就该在会话头 |
| 2 | `conversation.hero.options` | 空白会话页的「新建会话」选项行 | ✅ 合理：没有会话时唯一能去的地方 |
| 3 | **`sidebar.footer.action`** | **DSH 左侧栏底部、头像上方靠左** | ❌ **本轮撤掉** |

### 1.2 撤掉它的理由

1. **发现成本高于收益。** 用户几乎不会从头像旁边那个小图标去开工作台；工作台的入口已经有两个更显眼的位置。
2. **破坏宿主的视觉秩序。** 左侧栏底部是**宿主的**区域（头像、账户、设置），插件在那里插一个图标，等于在别人的地盘上贴广告。
3. **它还是「总是可见」的。** 代码注释自己写着它是 *"the always-present fallback"*（`index.jsx:805-807`）——但会话头那个入口其实**已经**是常驻的（第 1 项在有会话时必然存在），第 3 项的「兜底」价值并不成立。

### 1.3 规格

| 项 | 要求 |
|---|---|
| **ENTRY-01** | 删除 `sidebar.footer.action` 的槽位注册与 `OpenButton` 在该处的使用 |
| **ENTRY-02** | 会话头入口（`conversation.session.header.utilities`）与空白会话入口（`conversation.hero.options`）**保留**，行为不变 |
| **ENTRY-03** | 删除后，DSH 左侧栏底部**不再出现**工作台图标 |
| **ENTRY-04** | 快捷键打开工作台的路径**不变**（`store` 的工具窗快捷键、`F11`、设置项） |

> **风险**：`tests/render.test.mjs` 可能对槽位注册有断言。改动必须同步用例，且用例要断言**「不再注册 footer 槽位」**（正向断言「注册了它」在需求反转后毫无意义）。

## 2. 方向 B —— 视觉精修

### 2.1 问题诊断（用户原话 → 代码事实）

| 用户感受 | 代码事实 |
|---|---|
| 「平庸的字体」 | `--iwb-font` 是系统字体栈（`styles.js:113`），字号统一 13px，行高 1.45，**没有字号梯度**，标题与正文只差 `font-weight` |
| 「别扭的按钮」 | `.iwb-iconbtn` / `.iwb-textbtn`（`styles.js:174-195`）是**纯平面**的：无边框、无阴影、无渐变、无过渡（`transition` 一个都没有） |
| 「复古的图标按钮」 | 顶栏用了 **Unicode 字形**当图标：`⊟`（收起全部）、`⛶`（全屏）、`+`（新建）（`Workbench.jsx:127,134,1705`），Project 面板用了 `⌖`（文件定位）（`ProjectPanel.jsx:1701`）—— 这些字符在不同字体下渲染完全不同 |
| 「平得像纸的页面」 | 所有面板都是**同一个** `--iwb-panel` 底色 + 1px 硬边框，**没有任何高度差**（`--iwb-panel` / `--iwb-panel-2` 只在少数处使用），没有阴影、没有层次 |
| 「需要太多零碎说明小字」 | 大量 `font-size: 11px` 的说明文字与提示行 |

### 2.2 设计原则（这一轮的**审美宪法**）

> **P1 · 少即是多。** 一个好产品不该需要一堆小字说明就能用。
>      ⇒ 说明文字只保留**不可推断**的那部分；能靠图标与形状表达的，不写字。

> **P2 · 层次靠光影，不靠线条。** 表面之间用**明度差 + 阴影 + 高光**分层，1px 边框只用于真正的分隔。

> **P3 · 立体但不喧宾夺主。** 阴影是**环境光**（一层柔和的暗部 + 一层顶部高光），不是黑色描边。

> **P4 · 动效是质感的一半。** 所有可交互元素都有 **120–180ms** 的缓动过渡（`ease-out`），没有瞬变。

> **P5 · 科技感来自精度，不来自发光。** 细发丝线、等宽数字（`tabular-nums`）、克制的品牌色点缀。

### 2.3 规格

#### 2.3.1 设计令牌层（新增）

在 `.iwb-root` 上引入**成体系的令牌**，替换散落的字面量：

| 令牌族 | 内容 |
|---|---|
| `--iwb-radius-*` | `xs 4px / sm 6px / md 8px / lg 12px / pill 999px` |
| `--iwb-space-*` | `1 4px / 2 8px / 3 12px / 4 16px / 5 24px` |
| `--iwb-shadow-*` | `sm`（面板）/ `md`（浮层、弹窗）/ `lg`（模态）/ `inset`（输入框内阴影） |
| `--iwb-font-*` | `--iwb-font-display`（面板标题）/ `--iwb-font-ui`（正文）/ `--iwb-font-mono` |
| `--iwb-text-*` | `title 12px/600` / `label 11px/500` / `body 13px/400` / `mono 12px` |
| `--iwb-surface-*` | `base / raised / sunken / overlay / hover / active` —— **六个明确的表面级** |
| `--iwb-ease` | `cubic-bezier(.2, .8, .2, 1)` |
| `--iwb-dur` | `fast 120ms / normal 180ms` |

> **约束**：颜色令牌**仍必须**来自宿主的 `--dsw-alias-*`（`tests/styles-theme.test.mjs` 守着这条），
> 新令牌只是**派生层**，不得引入新的硬编码色板。

#### 2.3.2 字体与排版

| 项 | 要求 |
|---|---|
| **TYP-01** | 字体栈升级：`--iwb-font` 首选 `Inter`/`SF Pro`/`Segoe UI Variable`，再回落到系统栈；**必须**保留中文回退（`Microsoft YaHei UI` / `PingFang SC`） |
| **TYP-02** | 开启 `-webkit-font-smoothing: antialiased` 与 `text-rendering: optimizeLegibility`，消除 Windows 上的锯齿感 |
| **TYP-03** | 面板标题 / 次级标签 / 正文形成**三级字号梯度**（12 / 11 / 13），并给标题加 `letter-spacing: .04em` |
| **TYP-04** | 所有数字（行号、字数、增删行数、页码、列号）使用 `font-variant-numeric: tabular-nums` |
| **TYP-05** | 代码 / 终端 / diff 使用等宽字体，**并**收紧字距（`letter-spacing: -.01em`）以改善观感 |

#### 2.3.3 按钮

| 项 | 要求 |
|---|---|
| **BTN-V-01** | **图标按钮**（`.iwb-iconbtn`）：默认**无边框**（ghost）；hover 时出现 `--iwb-surface-hover` 底 + 轻微上浮（`transform: translateY(-.5px)`）；按下 `translateY(0)` + 内阴影 |
| **BTN-V-02** | **文字按钮**（`.iwb-textbtn`）：由「平面描边」改为「**渐变表面 + 顶部 1px 高光 + 柔和外阴影**」，形成实体感 |
| **BTN-V-03** | **主按钮**（`.iwb-primary`）：品牌色渐变 + 品牌色外发光（低透明度）+ hover 提亮 |
| **BTN-V-04** | 所有按钮带 **focus-visible** 焦点环（`box-shadow: 0 0 0 2px var(--iwb-bg), 0 0 0 4px var(--iwb-accent)`），键盘用户看得见 |
| **BTN-V-05** | 所有按钮有 `transition`（背景 / 边框 / 阴影 / 位移 / 颜色），时长走 `--iwb-dur` |
| **BTN-V-06** | 禁用态不是「变淡」了事，而是**降饱和 + 去高光 + `cursor: not-allowed`** |

#### 2.3.4 图标

| 项 | 要求 |
|---|---|
| **ICO-01** | **禁止**用 Unicode 字形（`⊟` `⛶` `+` `⌖` `▾` `×` `›` `●`）充当功能图标 —— 全部换成 `icons.jsx` 里的 SVG 图标 |
| **ICO-02** | 图标统一 `24×24` 视框、`stroke-width: 1.6`、`stroke-linecap: round`、`stroke-linejoin: round`（线性图标，不是实心块） |
| **ICO-03** | 新增本轮需要的图标：收起全部、全屏/还原、刷新、定位文件、新建、关闭、设置、筛选、折叠、展开 |

#### 2.3.5 表面与层次

| 项 | 要求 |
|---|---|
| **SURF-01** | 顶栏 / 面板头 / 状态栏用 `--iwb-surface-raised`，编辑区用 `--iwb-surface-base`，浮层用 `--iwb-surface-overlay` —— 四个级**明确不同** |
| **SURF-02** | 浮层（弹窗、右键菜单、提示）带 `md/lg` 阴影 + 1px 高光边，视觉上「浮」在内容之上 |
| **SURF-03** | 悬停行（树行、菜单项、文件行）用 `--iwb-surface-hover` 提亮，**不**用边框 |
| **SURF-04** | 选中态 = 品牌色**低透明度底 + 左侧 2px 品牌色标记**（已有 stripe 模式，推广到树行与菜单项） |
| **SURF-05** | 输入框 / 下拉：inset 阴影 + 聚焦时品牌色描边（不是系统默认描边） |

#### 2.3.6 减少小字（对应 P1）

| 项 | 要求 |
|---|---|
| **TXT-01** | 现有的**纯装饰性**提示行（不承载用户无法推断的信息）删除或降级为 tooltip |
| **TXT-02** | tooltip 承担「说明」的职责，界面正文里不再堆小字 |

### 2.4 验收

- 顶栏、Project 面板、编辑器、状态栏在明暗两种主题下都**层次分明**，无「平得像纸」的观感
- 全仓 `src/client/**` 中**没有** Unicode 字形充当功能图标（用例扫描源码）
- 所有交互元素有 hover / active / focus-visible 三态
- `tests/styles-theme.test.mjs`（不许硬编码配色）与 `tests/styles-literal.test.mjs` 保持全绿

## 3. 方向 C —— 稳定性加固

> 起因：一次真实使用中 **DSH 主进程渲染崩溃导致整个 DSH 崩溃重启**。排查后定位到工作台的两个隐患。

### 3.1 隐患一：终端输出没有任何上限

**事实**：
- 宿主 `src/index.js:844-847`：`handle.output.on('data', chunk => send({type:'data', data:text}))` —— **原样转发，一个字节不丢**。
- 客户端 `src/client/TerminalPanel.jsx:611-612`：`terminal.write(frame.data)` —— **直接写进渲染进程**。
- ⇒ 在工作台终端里 `cat` 一个大文件，字节会**无界地**灌进渲染进程的堆。

**规格**：

| 项 | 要求 |
|---|---|
| **TERM-01** | 宿主侧对**每个终端会话**设置输出字节上限（默认 **8 MiB**）。超过后：停止转发数据，发出一次 `{type:'truncated'}` 帧（带上限值与已传字节数），**如实告知**用户输出被截断 |
| **TERM-02** | 截断后**不关闭**终端会话（用户还能继续敲命令、继续看后续输出），只是不再转发历史输出 |
| **TERM-03** | 客户端收到 `truncated` 帧时，在终端里打印一行可见的提示（不是静默丢弃） |
| **TERM-04** | 客户端 xterm 的 `scrollback` 设**有界**（默认 5000 行），避免历史行无限堆积 |
| **TERM-05** | 上限值**可配置**（设置项），并有默认值兜底；非法值回落默认值 |
| **TERM-06** | 用例：宿主在超过上限时**必须**发出且只发出一次 `truncated` 帧，且转发字节数**不超过**上限 |

### 3.2 隐患二：PDF 整文件 base64 塞进 JSON

**事实**：
- 宿主 `src/host/workspace.js:299-307`：把 **≤32 MiB** 的 PDF 读成 base64（**约 42.7 MiB 的字符串**），随 `fs.read` 的 JSON 返回。
- 客户端 `src/client/store.js` 把整个 JSON 塞进 store；`src/client/pdf-engine.js:103` 交给 pdf.js。

**规格**：

| 项 | 要求 |
|---|---|
| **PDF-01** | `fs.read` 对 PDF **不再返回字节**：只返回元信息（`kind:'pdf'`、`size`、`mtimeMs`、`path`） |
| **PDF-02** | 新增一条**二进制**路由（`GET /ide-workbench/raw/<…>`），按字节返回 PDF，带 `Content-Type: application/pdf`、`Content-Length`、`Cache-Control: no-store` |
| **PDF-03** | 二进制路由**必须**过宿主围栏（`fence(req)`）与工作区围栏（`resolveInside`）—— 与其它路由同等级别 |
| **PDF-04** | 客户端改用 `fetch → arrayBuffer()` 取字节，交给 pdf.js 的 `getDocument({ data })` |
| **PDF-05** | 客户端在 store 里**不留存** PDF 字节（只留元信息）；字节在渲染器里用完即弃 |
| **PDF-06** | 超过上限的 PDF 仍按现状返回 `kind:'too-large'`（不回归） |
| **PDF-07** | 密码保护 / 损坏的 PDF 仍给出明确提示（不回归） |

> **口径**：**JSON 里再也不出现 PDF 字节**。一个大 PDF 不应该让整个 JSON 响应膨胀 33%。

## 4. 方向 D —— 交互收敛

### 4.1 Project 面板头部的四个按钮

**现状**（`src/client/ProjectPanel.jsx:1692-1709`）：筛选、文件定位、新建、刷新。

| 按钮 | 用户判断 | 本轮处置 |
|---|---|---|
| 筛选（放大镜） | 保留 | ✅ **保留**，图标换成新 SVG |
| 文件定位（`⌖`） | 功能对，图标意义不明 | ✅ **保留功能**，换成「十字准星 / 目标」SVG 图标（**ICO-01**） |
| 新建（`+`） | 鸡肋：只能在项目根建一个文件 | ❌ **删除**（新建收口到右键菜单 + Alt+Insert） |
| 刷新 | 保留 | ✅ **保留**（刷新文件树，与顶栏的重复刷新不同职责 —— 见 4.2） |

### 4.2 工作台顶栏的四个按钮

**现状**（`src/client/Workbench.jsx:124-141`）：收起全部、全屏/还原、刷新、设置。

| 按钮 | 用户判断 | 本轮处置 |
|---|---|---|
| 收起全部（`⊟`） | 作用不大，白占位置 | ❌ **删除**（快捷键 `Ctrl+Shift+F12` 保留） |
| 全屏/还原（`⛶`） | 与宿主侧栏的全屏按钮**功能重叠** | ❌ **删除**（宿主右栏的全屏按钮 + `F11` 保留） |
| 刷新 | 与 Project 面板的刷新**互相冗余** | ❌ **删除**（刷新收口到 Project 面板） |
| 设置（齿轮） | 唯一不可替代的 | ✅ **保留**，换成新 SVG 图标 |

> **纪律**：删掉的按钮，其**功能入口一个都不能少**（快捷键 / 右键菜单 / 宿主按钮）——
> 「删按钮」是**收口**，不是「砍功能」。

### 4.3 Alt+Insert 新建类型歧义

**现状**（`src/client/ProjectPanel.jsx:1410-1416`）：
`Alt+Insert` 永远打开**文件**对话框；右键菜单里「新建文件」与「新建目录」**两项都标着 `Alt+Insert`**，
用户按下快捷键后无法选择类型 —— 「想建目录却建出文件」就是这么来的。

**规格**：

| 项 | 要求 |
|---|---|
| **NEW-01** | `Alt+Insert` 打开的新建对话框**自带类型切换**：对话框顶部有「文件 / 目录」分段选择（segmented control），默认**沿用上一次的类型**（记忆在组件状态里） |
| **NEW-02** | 右键菜单的「新建文件」「新建目录」两项**各自标注自己的快捷键**：`Alt+Insert`（文件）与 `Alt+Shift+Insert`（目录）——两者不再共用同一个提示 |
| **NEW-03** | `Alt+Shift+Insert` 直接打开**目录**对话框 |
| **NEW-04** | 类型切换时，对话框标题、模板下拉（仅文件有）、提交结果**全部跟着变** |
| **NEW-05** | 对话框里不再出现「新建文件…」「新建目录…」两个近乎相同的菜单项造成的歧义；菜单保留两项（用户要的是「直接建某个类型」），但**快捷键提示不再撒谎** |

### 实现备注（图片拖动的根因）

`src/client/ImageViewer.jsx:152-160` 的 `onMove` 用的是**从拖动起点算起的累计位移**，
却把它**加到当前的 pan 上**：

```js
const dx = event.clientX - drag.x      // 累计位移
pan: clampFor({ x: previous.pan.x + dx, ... })  // 又加到当前 pan 上
```

⇒ pan 随移动次数**平方增长** ⇒ 轻轻一拖就撞到钳位 ⇒ 「直接跳到最左边」。
**修法**：拖动开始时记下 `pan` 起点，移动时用 `起点 pan + 位移`（**绝对式**，不是累加式）。
