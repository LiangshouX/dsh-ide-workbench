## 1. 缺陷：DSH 的设置页白屏（回归）

### 1.1 机制

`SettingsForm` 在重设计里改成**只读三块 slice**（`settings` / `shells` / `localeTick`），
而 **DSH 原生的 `settings.section` 页面**走的正是这条路径：

- `src/client/index.jsx:419-422` → `BoundSettings` → `SettingsSection({ store, state })`
- `src/client/SettingsPanel.jsx:836-843` → `SettingsSection` 读 slice，把 `{ store, settings, shells, localeTick }` 交给 `SettingsForm`
- **`SettingsForm` 收到的是 `state === undefined`**

改动前那一行是：

```js
const entrySide = state.settings?.layout?.entrySide === 'left' ? 'left' : DEFAULT_ENTRY_SIDE
```

`state.settings` 在 `state` 为 `undefined` 时抛 `TypeError` —— `?.` 只保护了 `settings`，
**没有保护 `state` 本身**。表单在渲染期抛错，React 卸载整棵子树 → **白屏**。 [读码确认]

工作台自己的模态框不受影响：它传的是完整的 `state`。所以这个缺陷**只在 DSH 的设置里出现**，
和用户描述的「设置只在侧栏生效，DSH 的设置里面是白屏」完全一致。 [读码确认]

### 1.2 修法

```js
const entrySide = settings.layout?.entrySide === 'left' ? 'left' : DEFAULT_ENTRY_SIDE
```

`settings` 是 `settingsProp ?? state?.settings ?? {}`：**原生页面走 slice，模态框走 state**，
两边拿到的都是**活值**（不是草稿），语义与原来一致。

### 1.3 防回归

- `tests/settings-page.test.mjs` 新增「the native page of DSH renders without a state of the store」：
  用服务端渲染跑**真正的 `SettingsSection`**（不带 `state`），断言它渲染出面板与行。
- `tests/toolwindow-side.test.mjs` 新增一条**禁止性**断言：
  `assert.doesNotMatch(settingsPanel, /(?<![\w?])state\.[a-zA-Z]/)` ——
  表单**不允许**再直接解引用 store 的 state（`state?.x` 允许）。 [读码确认]

## 2. 画面太跳：面板定高

### 2.1 机制

十个分类的行数从 1（删除）到 17（快捷键）不等。面板**跟着内容长高**，
于是换一个分类，**模态框就换一个高度**。 [读码确认]

### 2.2 修法

`.iwb-settings-panel` 从「没有高度」改成**有高度**：

```css
--iwb-settings-panel-height: min(50vh, 520px);   /* 紧凑密度 min(44vh, 420px) */
.iwb-settings-panel { height: var(--iwb-settings-panel-height); overflow-y: auto; overscroll-behavior: contain; }
```

是 `height` 而**不是** `min-height`：`min-height` 仍会让窗口随最长的分类长高。
行在面板**内部**滚动。 [读码确认]

### 2.3 实测

在真机上逐个切换分类，面板高度**恒定**：

| 分类 | 面板高 | 需要内部滚动 |
|---|---|---|
| 全部 45 | 337 px | 是 |
| 通用 2 | 337 px | 否 |
| 快捷键 17 | 337 px | 是 |
| 删除 1 | 337 px | 否 |
| 布局 1 | 337 px | 否 |
| 终端 4 | 337 px | 否 |

工作台自己的模态框高度**恒定 521 px**（三个分类实测相同）。 [实测确认]

### 2.4 防回归

`tests/styles-theme.test.mjs` 新增「the panel of the settings keeps its height when the category changes」：
断言 `height: var(--iwb-settings-panel-height)` 与 `overflow-y: auto` 存在，
并断言 `.iwb-settings-panel` 里**没有** `min-height`。 [读码确认]

## 3. 分类标签太挤：一行 + 横向滚动条

### 3.1 机制

改前是 `flex-wrap: wrap` + 24px 高的小 chip。在窄容器里十个 chip **换行堆成一堆**，
读起来是一片噪音；而且上一轮引用的技能条目 *Chip Collection Reflow*（chip 换行而非裁剪）
在这里**用错了地方**——它防的是「裁掉」，但用户要的是「别堆」。 [读码确认]

### 3.2 修法

```css
.iwb-settings-tabs {
  display: flex; flex-wrap: nowrap; gap: var(--iwb-space-2);
  overflow-x: auto; overflow-y: hidden;
  scrollbar-width: thin; scrollbar-color: var(--iwb-border-strong) transparent;
}
.iwb-settings-tabs::-webkit-scrollbar { height: 6px; }
.iwb-settings-tab { height: 32px; padding: 0 14px; gap: 8px; flex: 0 0 auto; border: 1px solid var(--iwb-border); }
.iwb-settings-tab[aria-selected="true"] { border-color: var(--iwb-accent); font-weight: 600; }
```

- **不再换行**：一行放不下就**拖滚动条**（用户原话：「太挤堆在一起的话就用滑动条拖」）。
- chip **加大**：32px 高、14px 左右内边距、8px 间距、有边框 —— 「大气一点」。
- 选中项有 accent 边框与 600 字重，一眼可辨。
- 选中分类若在视野外，`selectTab` 会 `scrollIntoView({ inline: 'nearest' })` **把它带进视野**，
  否则用户点了分类却「什么都没发生」。 [读码确认]

### 3.3 实测

- 侧栏（573 px 视口）：分类内容 640 px → **横向可滚**。
- DSH 设置页（564 px 视口）：分类内容 966 px → **横向可滚**，滚动条可见。

### 3.4 防回归

`tests/styles-theme.test.mjs` 新增「the category bar scrolls instead of piling the chips up」：
断言 `flex-wrap: nowrap` 与 `overflow-x: auto` 存在、`flex-wrap: wrap` **不**存在、
并且有一条自定义滚动条规则。 [读码确认]

## 4. 瘦身：删掉没人读的设置

### 4.1 先核数：**是 12 个，不是 14 个**

上一轮的清单里有两个是**活的**，差点被误删。逐个复核（读码确认）：

| 键 | 结论 | 证据 |
|---|---|---|
| `editor.sideBySide` | **活的** | `src/client/store.js:758`（`mode: settings?.editor?.sideBySide === false ? 'unified' : 'side'`）、`store.js:3036`（写回） |
| `git.wordLevel` | **活的** | `src/client/diff.js:390-391`（`wordLevelDefault`）、`src/client/DiffView.jsx:85,393-395`（读与写） |
| `editor.wordWrap` | 没人读 | 全文只有默认值 |
| `git.diffStyle` | 没人读 | 同上（`git.compare` 是**另一个**东西：比较标签的状态） |
| `git.structuralOnly` | 没人读 | 同上 |
| `git.logPageSize` | 没人读 | 同上 |
| `delete.confirm` | 没人读 | `state.confirm` 是确认弹窗的状态，与设置无关 |
| `ui.showStatusBar` | 没人读 | 只有默认值与宿主校验 |
| `terminal.cwdMode` | 没人读 | 只有默认值 |
| `shortcuts.compare` | 没人读 | `shortcutFor()` 的调用点里没有它 |
| `shortcuts.renameRefs` | 没人读 | 同上 |
| `shortcuts.searchEverywhere` | 没人读 | 同上 |
| `shortcuts.revertCommit` | 没人读 | 同上 |
| `shortcuts.openEntry` | 没人读 | 只躺在 `ProjectPanel.jsx` 的 fallback 表里，没有消费方 |

**真正没人读的是 12 个**（`sideBySide` 与 `wordLevel` 保留）。 [读码确认]

### 4.2 怎么删的

- `src/host/settings-store.js`：`DEFAULT_SETTINGS` 去掉这 12 个键；
  新增导出 `DEAD_SETTINGS`（`[section, key]` 清单）与 `dropDeadSettings(value)`。
- `SETTINGS_VERSION` **5 → 6**，并在文件头的版本说明里写清这一步是**唯一一次破坏性**的迁移
  （版本变更会写一份备份 `settings.json.v5.bak.json`）。 [读码确认]
- `migrateSettings()` 调用 `dropDeadSettings()`：**老文档里带的死键在读的时候被取走**，
  用户的其它设置一个不动。
- `update()` 在写盘前也调用一次：**一个还认识旧键的客户端写它，文档也不会把它收回来**。 [读码确认]
- `src/client/ProjectPanel.jsx`：`SHORTCUT_FALLBACK` 去掉 `compare` / `openEntry`
  （它们对应的设置已经不存在了）。

### 4.3 实测（真机 profile）

`C:\Users\X-L-S\.dsh\profiles\desktop\ide-workbench\settings.json`：

- `version`：**5 → 6**
- 12 个死键：**全部不在了**
- 活着的设置**全在**：`sideBySide`、`wordLevel`、`density`、`openCommitDetail`、`hideAll`
- codeintel 的 `lsp` 段：**还在**（迁移只动 core 自己的键）
- 备份：`settings.json.v5.bak.json` 已写出

### 4.4 防回归

`tests/settings-migration.test.mjs` 新增三条：

- 「the defaults hold no setting that nothing reads」—— 12 个键**不在默认值里**，
  且断言两个**活的**设置（`sideBySide` / `wordLevel`）**还在**。
- 「a document that carries a dead setting loses it」—— 迁移取走死键，用户的设置留着。
- 「a write does not bring a dead setting back」—— 写一个死键，文档里也不留。

`tests/settings-search.test.mjs` 的「没人在页面上」清单从 14 项改成**真正的 12 项**
（`sideBySide` / `wordLevel` 是活的，不该出现在那份清单里）。

## 6. 遗留

- **`editor.sideBySide` 与 `git.wordLevel` 仍是活的、但不在设置页上** —— 它们由 diff 视图
  工具栏上的「并排 / 单词级差异」两个按钮直接切换，一步可达。这一轮按「只删没人读的」的口径
  没有动它们；要不要把它们也搬进设置页，等下一次决定。
- 面板高度用的是 `vh`，在**极矮**的窗口（< 450 px）里 50vh 会偏小；模态框本身有
  `max-height: 82%` 兜底，不会溢出，但可用高度会紧张。 [推断，未实测极矮窗口]
- 横向滚动条在**深色主题**下的对比度只做了令牌继承，没有单独核对每一套主题。 [推断]
