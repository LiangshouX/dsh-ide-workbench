## 1. U1：跨层用例补上「服务器被替换」

### 1.1 报告说得对：这是一个真的缺口

T1 是**跨侧**的不对称——「宿主发布了代号 / store 镜像了代号 / 客户端在轮询里看到了」
这三件事**必须同时成立**才对。三段单侧用例各自都能绿，但**它们之间的接线**断了也能全绿：

| 环节 | 谁守住 | 类型 |
|---|---|---|
| 宿主发布代号 | `tests/lsp-recovery.test.mjs` | 单侧 |
| store 镜像代号 | `tests/lsp-client-budget.test.mjs`（mock `status`） | 单侧 |
| 客户端观察代号并复位 | `tests/lsp-client-budget.test.mjs`（手动 `setProcessId`） | 单侧 |
| **两端接起来** | **无** | — |

### 1.2 补的用例

`tests/lsp-budget-agreement.test.mjs` 的第三条：
**真实的宿主 manager → 真实的 store → 真实的客户端**，只有客户端的传输层（`fetch`）
被换成宿主 manager 的真实回答——这正是浏览器与宿主之间本来就有的那道缝。

它做的事：

1. 起一个真实的 manager，客户端发一个语义请求，服务器回答 → 两侧都变「严格」；
2. 让服务器**真的崩溃**（`handle.exit(1)`）→ 宿主真的重启 → `processId` 变了；
3. **真实的 store** 轮询状态（`store.refreshLspStatus()`）→ 镜像新的代号；
4. 断言：**宿主与客户端同时回到「长预算」**。

### 1.3 变异测试：它真的抓得住

把 store 的合并里那一行代号（`processId: Number.isFinite(status.processId) ? … : 0`）
改成 `processId: 0`（模拟「某次重构把代号漏掉」）：

```
=== mutation: the store drops the identity ===
ok 1 - the host and the client are patient in the same way
ok 2 - an answer that is not semantic changes neither side
not ok 3 - a replaced language server puts both sides back on the long budget
```

**前两条单侧用例照样绿，第三条变红**——正是报告描述的那个场景。改回来又全绿。

## 2. U2：请求被计为超时后，状态栏不再说「正在构建索引」

`#checkTimeouts` 把一个请求记成超时时会把它从 `pendingRequests` 里删掉（它只被计一次），
而 `isBuildingProgram` 的第二个条件是「**有一个语义请求还挂着**」——于是请求一被计数，
标志就变 false，状态栏从「正在构建索引…」退回「就绪」。

**没有改，理由**：

- 走到这一步已经过了 **10 分钟**（长预算），而客户端那边早就超时了 —— 状态栏此时显示的
  已经是「**不稳定**」（失败分支在 `buildingProgram` 之前），`buildingProgram` 根本不参与
  显示；
- 也就是说这个缺口**在界面上不可达**，改它要动生产代码（多一个会话计数器）却换不到
  任何用户可见的改善。

若将来要改，方向是报告给的那条：用「自上次真实回答以来**曾有**一个语义请求」这个
**粘性**标志，而不是依赖「当前还挂着」。

## 3. U3：客户端的 `lastProcessId` 是全局的，`processId` 是按 root 的

两个不同项目的代号可能相同（各自的第一个进程都是 1），切到另一个项目时客户端会看到
「代号没变」而不触发复位。

**今天无害**：项目切换本身会复位预算——`refreshLsp()` 在 `previousRoot !== root` 时调用
`resetLspHealth()`，`stopLsp()` / `startLsp()` 也会。

**没有改，理由**：报告自己给的修法（「把 `lastProcessId` 改成按 root 记录」）有一个
前提问题——客户端的 root 是**工作区**根，宿主的 `processId` 是按**语言服务器的项目根**
算的，两者不一定相同（工作区根常常只是容器）。按工作区根建 Map 并不能精确对应宿主
那份按项目根的代号。要做对，就得让客户端记录**它实际连着的那个语言服务器根**。

而现状的失效需要一个前提：有人把「项目切换时复位预算」那条路径删掉（它现在看起来像
冗余）。所以本轮把它**写进文档**而不是改成代码。
