## 二、需求详述

### R1 — 聊天文件链接重复点击，第 2 次起落到侧栏标签

**优先级** P1 ｜ **类型** Bug（落点不确定 + 残留 UI）

> ✅ **已定**：**始终在 IDE 工作台内打开**；首次点击进入工作台，**再次点击只聚焦已有的文件标签页**（不新开、不重复加载）。

**现状**
聊天消息里的同一个文件链接：第 1 次点击在 IDE 工作台内打开（Project 树展开 + 编辑器定位）；再次点击同一链接，右侧栏出现一个**永远停在"加载中"的标签页**；第 3 次点击时不再进入工作台，只是把那个残留标签页置前。

**期望**
1. 同一文件地址连续点击 ≥3 次，**每次都进 IDE 工作台**；再次点击**只聚焦已有的文件标签页**（不新开、不重复加载）；
2. 右侧栏**不出现**任何以文件地址为 contentId 的残留标签页；
3. 承载 tab 的最终归宿可判定：**被宿主替换** 或 **被插件显式关闭**，二者必居其一（不允许悬空）；
4. 工作区外文件 / 二进制 / Office / PDF 仍按现状降级到宿主侧栏（**不得回归**）。

**复现**
1. 打开有工作区的会话，IDE 项目已选定；
2. 聊天里输出一个工作区内的文件链接（或 `@` 一个工作区内文件并发送）；
3. 第 1 次点击 → 右侧栏出现 IDE 工作台标签，Project 树展开、文件在编辑器区打开；
4. 再次点击同一链接 → 出现/保留一个停在"加载中"的标签页；
5. 第 3 次点击同一链接 → 点击不再进入工作台。

**验收标准**
- [ ] 同一链接连续点击 ≥3 次，每次都在 IDE 工作台内打开；再次点击只聚焦已有文件标签页，不新开
- [ ] 右侧栏不出现任何以文件地址为 contentId 的残留标签页
- [ ] 第 2 次起不出现永久停在"加载中"的标签页
- [ ] 设置项 `links.chatFiles='ide'`（默认）与 `='sidebar'` 两种取值行为各自稳定一致
- [ ] 工作区外 / 二进制 / Office / PDF 的降级路径不回归

**涉及模块**：`src/client/index.jsx`（FileLinkBridge / 承载 tab 替换协议）、`src/client/store.js`（`openExternalFile`）、`src/client/file-link.js`

**根因提示**：插件用"宿主两步承载 tab"协议，判定"已替换"仅依据 `openTab` 未抛异常；宿主在目标页面 tab 已存在时只聚焦、不执行替换，承载 tab 残留并命中宿主去重键，导致后续点击被吞掉。

### R2 — 回合变更预览链接只能在侧栏打开

**优先级** P1 ｜ **类型** 缺失（能力增强）

> ✅ **已定**：**链接抢下** —— 变更预览链接默认在 **IDE 工作台内**展示；参照现有设置项【聊天文件链接】（`links.chatFiles`）可切换为「IDE 工作台 / 默认 DSH 侧栏」。
> **硬性要求**：IDE 工作台内的展示效果**不得比默认（宿主侧栏）效果差**。
> 工作区之外的回合变更文件：**只读展示**；若在工作台内打开出现故障，**降级到默认侧边栏**。

**现状**
一轮对话结束后若该轮有文件变更，聊天消息末尾会给出变更预览链接（点击展示 diff）。该 diff **只能**在 DSH 宿主右侧栏标签页中打开，IDE 工作台内没有任何入口。

**期望**
1. 变更预览链接**默认在 IDE 工作台内**打开，与普通文件链接体验一致；
2. 复用设置项【聊天文件链接】（`links.chatFiles`）：可切换为「IDE 工作台 / 默认 DSH 侧栏」；**IDE 工作台内的展示效果不得比默认（宿主侧栏）效果差**；
3. 工作台内能显示本回合的变更文件列表（路径、显示名、增删行数）与选中文件的 diff，并支持统一 / 并排视图切换；
4. 链接携带的文件下标参数被尊重：**打开时直接定位到该文件**，而不是永远显示第 1 个；
5. 二进制 / 超大变更有明确提示，**不空白、不报错**；
6. **工作区之外的回合变更文件：只读展示**；若在工作台内打开出现故障，**降级到默认侧边栏**；
7. 会话或工作区切换后，历史回合链接行为一致，不出现半死状态；
8. **回归**：普通文件链接的认领与打开行为零变化。

**复现**
1. 打开有工作区的会话；
2. 让模型修改工作区内某文件；
3. 本轮结束 → 聊天末尾出现变更预览链接；
4. 点击 → diff 出现在宿主右侧栏标签页；
5. 对比：同一会话点普通文件链接 → 文件出现在 IDE 工作台内。

**验收标准**
- [ ] 点击变更预览链接 → 默认在 IDE 工作台内打开该回合变更视图
- [ ] 工作台内展示变更文件列表 + 选中文件 diff，统一/并排可切换
- [ ] 链接参数指向的文件被正确定位（不是永远第 1 个）
- [ ] 二进制 / 超大变更有明确提示，不空白不报错
- [ ] 设置项可切换「IDE 工作台 / 默认 DSH 侧栏」，且工作台内效果不劣于宿主侧栏
- [ ] 工作区外的回合变更文件只读展示；工作台打开故障时降级到默认侧栏
- [ ] 普通文件链接行为零变化（现有相关断言全部保持通过）

**涉及模块**：`src/client/index.jsx`（tab 类型注册与分流）、新增回合变更地址解析模块、`src/client/store.js`（回合 diff 数据装载）、`src/client/diff.js` / `DiffView.jsx`（渲染）、`src/index.js`（数据路由）

**根因提示**：工作台**从未认领** `dsh-resource://changes-review/**` 这类地址，在宿主 tab 注册表的匹配阶段即出局 → 宿主自带的 review tab 恒定胜出。另：回合 diff 数据是**结构化 hunks**，与现有 git 口径的 unified diff 文本不是同一份数据。

> **附带需求（可选）**：即便不在工作台内实现变更预览，也要在工作台内提供"查看本回合变更"的入口。

### R3 — 无 JSON / 类·方法·函数折叠，无一键折叠展开快捷键

**优先级** P2 ｜ **类型** 缺失（能力增强）

> ✅ **已定**：快捷键绑定为**全部折叠 / 全部展开**，采用 **IntelliJ 风格**（`Ctrl+Shift+-` / `Ctrl+Shift+=`）；**不做可配置**。

**现状**
编辑器（CodeMirror）**一行代码都不能折**：JSON 的对象/数组无折叠标记，代码的类 / 方法 / 函数体也无折叠 gutter；`Ctrl+Shift+[` / `]` / `-` / `=` 等一键折叠展开快捷键**无任何反应**。

**期望**
1. 打开任意 `.json`，对象/数组左侧出现折叠标记，点击可收起/展开，JSON 高亮不受影响；
2. 打开 `.ts/.js/.java/.py/.go/.rs` 等，类体 / 方法体 / 函数体左侧出现折叠标记；
3. 折叠标记可点击、可用键盘触发；折叠后显示占位符，不破坏撤销历史；
4. 提供"**一键折叠全部 / 一键展开全部**"快捷键（IntelliJ 风格：`Ctrl+Shift+-` / `Ctrl+Shift+=`），编辑器聚焦时生效，**不做可配置**；
5. 折叠 gutter 颜色跟随宿主主题，**不得硬编码颜色**；
6. 只读预览、Markdown 源视图不受影响。

**复现**
1. 打开工作台 → Project → 双击任意 `package.json`（或任意 `.ts`）；
2. 观察行号左侧：**没有任何折叠标记**；
3. 按 `Ctrl+Shift+[` / `]` / `-` / `=`：**无任何反应**。

**验收标准**
- [ ] JSON 对象/数组可折叠
- [ ] 代码类/方法/函数级可折叠
- [ ] 折叠标记可点击、可键盘触发，占位符正常，不破坏撤销历史
- [ ] 一键折叠全部 / 展开全部快捷键可用（`Ctrl+Shift+-` / `Ctrl+Shift+=`，编辑器聚焦时）
- [ ] 折叠 gutter 颜色跟随宿主主题（走主题变量，无硬编码）
- [ ] 只读预览与 Markdown 源视图不受影响

**涉及模块**：`src/client/CodeEditor.jsx`（扩展装配 + 快捷键绑定）、`src/client/styles.js`（折叠样式）、必要时 `src/client/util.js`（快捷键归一化）

**根因提示**：折叠相关 API **已在依赖里且已内联进产物**，缺的只是"装上 `codeFolding()` / `foldGutter()`"与快捷键绑定。另需注意：本仓库的快捷键归一化把 `Ctrl+Shift++` 解析坏（`split('+')`），CodeMirror 侧必须写成 `Ctrl-Shift-=`。

### R4 — 长文件树没有顶部冻结目录

**优先级** P2 ｜ **类型** 缺失（能力增强）

> ✅ **已定**：**面包屑式**冻结 —— 顶部固定条显示**从项目根开始的完整目录链路**，**每一步都可点击跳转**；空间不够时**先省略中间的目录**，再不够时**连项目根一起省略**（只剩末级）。
> ❗ **2026-11-11 变更**：原决策为「只冻结到直接父目录（一级）」。实机点击后发现只显示一级名字**看不出树在哪**，故改为完整链路 + 两级省略。

**现状**
Project 面板文件树很长时，**没有任何"当前所在目录"的指示被钉在顶部**。面板头虽有 32px 固定条，但只显示工程根目录名，不反映滚动位置。想折叠当前目录必须向上滚回该行再点。

**期望**
1. 树滚动到较深目录时，顶部出现冻结的**面包屑条**，显示**从项目根开始的完整目录链路**（`项目根 › 一级 › 二级 › 当前目录`），**每一步都可点击跳转**；
2. 面包屑随滚动实时更新（不闪烁、不滞后）；
3. 点击面包屑中的目录可跳转 / 选中；点击折叠标记可直接折叠该目录；
4. 顶部面板头保持可见（**当前已满足，不得回归**）；
5. 空间不够时**先省略中间的目录**（`项目根 › … › 当前目录`），再不够时**连项目根一起省略**（`… › 当前目录`）；末级永远保留；
6. 短树 / 未滚动时不出现冻结条（或与普通行无视觉差异）；
7. 虚拟化不回归：10k 文件仓库滚动仍流畅；
8. 过滤模式（快速文件列表，无目录层级）下不显示冻结条。

**复现**
1. 打开含大量子目录的工程 → Project 面板；
2. 展开多层目录并向下滚动；
3. 观察：顶部没有任何"当前目录"指示被钉住。

**验收标准**
- [ ] 滚动深处时顶部出现冻结的祖先目录行
- [ ] 冻结行内容随滚动实时更新，无闪烁无滞后
- [ ] 冻结行可折叠 / 可选中 / 可展开
- [ ] 面板头保持可见（不回归）
- [ ] 短树或未滚动时不出现多余冻结行
- [ ] 10k 文件仓库滚动流畅（虚拟化不回归）
- [ ] 过滤模式下隐藏冻结层

**涉及模块**：`src/client/ProjectPanel.jsx`（行渲染、滚动容器、冻结层）、`src/client/styles.js`（冻结条样式）

**根因提示**：树行是**绝对定位**（虚拟滚动），CSS `position: sticky` 对其无效 ⇒ 必须另做一层冻结行，且其内容要由行模型重新生成（被滚出视口的祖先行并未挂载）。

### R5 — 包链目录不折叠；新建弹窗不能选父目录

**优先级** P1 ｜ **类型** 缺失（能力增强）

> ✅ **已定**：合并标签用**点号 `.`** 连接；若某个目录名本身含点号，显示时**用斜杠标注**以示区分；折叠策略 = **只折叠已加载的链**（零额外 IO）。
> **合并节点的右键语义**：新建 / 删除**针对叶子目录**；**重命名对合并节点禁用**（或只改最后一段）。
> **新建弹窗路径框**：默认值 = **完整相对路径**；编辑后的**解析基准 = 项目根**；**跨出项目根一律拒绝**。

**现状**

- **（A）树**：目录链**一级一行**，无任何合并。形如 `src/main/java/com/liangshou/adapter/controller` 的包链会展开成 7 层缩进 7 行。
- **（B）弹窗**：新建目录/文件弹窗**只有"填写名称"一个输入框**，无法指定创建位置。

**期望**

**（A）目录链折叠**
1. 对 `src/main/java/com/liangshou/adapter/controller` 这类路径，**从 `com` 起是包链**，链上没有任何目录/文件；应按 IDE 的做法**折叠为 1 个父目录节点**，只在**真正开始分叉**的节点处分叉树枝；
2. 合并标签用**点号 `.`** 连接（`com.liangshou.adapter.controller`）；**若某个目录名本身含点号，该段用斜杠标注**以示区分；
3. 展开后**直接看到叶子文件**（不再需要逐级点开）；
4. 链上任一层出现"多个子目录"或出现"文件"时，从该层开始分叉；
5. 合并节点仍携带正确的 Git 状态色与排除背景；
6. 右键合并节点 → "新建文件/新建目录"的父目录 = 该合并节点对应的**真实叶子目录**；
7. 合并节点的**删除**同样作用于叶子目录；**重命名对合并节点禁用**（或只允许改最后一段）；
8. 键盘 `ArrowLeft` 从叶子文件回到父行时，跳到**最近的可见祖先行**（不能因合并而失效）；
9. 虚拟滚动与树的重算性能不回退；
10. 折叠范围限于**已加载的链**（零额外目录读取；未加载的深层链不预读）。

**（B）新建弹窗支持选父目录**
1. 名称框旁新增一个"整个折叠路径"输入框，默认值 = 目标位置的**完整相对路径**；
2. 该框**默认置灰不可编辑**，**鼠标点进去即激活**（用只读 + 置灰样式，不能用 disabled —— disabled 无法点击聚焦）；
3. **不编辑时仍从直接父目录新建**；**只有当该框被编辑过**才改变创建位置；
4. 编辑后的路径**以项目根为解析基准**；**跨出项目根一律拒绝**（给出提示，不落文件）；
5. 编辑为多级路径并创建 → 生成该路径，**缺失的中间目录自动创建**；
6. 非法输入（`..`、绝对路径、越出工作区、空段）被拒绝并给出提示，**不落任何文件**；
7. 创建后树自动展开到新文件；
8. 文件模板下拉行为不变，Enter 提交仍可用。

**复现**
- （A）展开 `src/main/java/com/liangshou/adapter/controller` → 观察 7 层缩进逐级展开。
- （B）右键任一目录 → 新建目录 → 弹窗只有名称框，无法在主干中间插入。

**验收标准**
- [ ] 包链折叠为一行，标签为点号连接的合并串（目录名本身含点号时该段以斜杠标注），`title` 为完整相对路径
- [ ] 展开后直接看到叶子文件
- [ ] 链上出现分叉或文件时从该层分叉
- [ ] 合并节点 Git 状态色 / 排除背景正确
- [ ] 合并节点右键"新建"的父目录为真实叶子目录
- [ ] 合并节点"删除"作用于叶子目录；"重命名"对合并节点禁用（或只改最后一段）
- [ ] 键盘 ArrowLeft 回退到最近的可见祖先行
- [ ] 仅折叠已加载的链，不触发额外目录读取
- [ ] 弹窗路径框默认值为完整相对路径，点击后可编辑，不编辑时创建位置不变
- [ ] 编辑后的路径以项目根为基准解析；跨出项目根被拒绝且不落文件

3. 点击 **Chrome 按钮** → **没有任何浏览器窗口弹出**，也**没有任何错误提示**；
4. 点击 **地球按钮** → 侧栏正常打开并渲染出 HTML ✅

**验收标准**
- [ ] Windows 上点击后**用户注册的默认浏览器**被唤起并显示该 HTML（相对路径资源正常加载）
- [ ] 标签页有未保存修改时不打开，并给出提示
- [ ] 无法确定浏览器 / 启动失败时弹出可读错误提示，不静默
- [ ] 宿主能区分"已成功派发"与"派发后无反应"
- [ ] `http:` / `https:` 现有行为不变
- [ ] 新增回归用例：**Windows + `file://`**（当前完全缺失），以及一条"失败必须有提示"的用例
- [ ] 按钮图标 / 文案与真实行为一致
- [ ] 「在侧栏预览」路径不破坏

**涉及模块**：`src/host/shell.js`（外部打开执行）、`src/client/store.js`（`openInDefaultBrowser`）、`src/client/EditorArea.jsx`（按钮与图标）、`src/client/file-address.js`（URL 构造）、`src/client/i18n.js`（文案）、README（功能描述）

**根因提示**：
1. Windows 分支用「URL 协议处理器」派发 URL，而 `file:` 在 Windows 上**不是有 open 动词的 URL 协议**（由 shell 按文件关联处理）⇒ 该入口对 `file://` 一律"启动成功但什么都不做"，且进程本身不报错；
2. 成功判定建立在"子进程已 spawn"上，**从不检查退出码**，标准输出/错误也被丢弃 ⇒ 宿主永远回"成功"，客户端永远走成功分支，**这就是静默失效**；
3. 次要：「默认浏览器」与「文件关联」被混为一谈 —— `file:` 不受 http 的用户默认浏览器设置管辖，只受 `.html` 文件关联管辖；而按钮画的是硬编码 Chrome 图标、文案是"用默认浏览器"。

## 三、附加需求（不属原始 11 条）

### A1 — Markdown / TXT 的词数 / 字数统计

**优先级** P2 ｜ **类型** 新增 ｜ **状态：口径与全部实现细节已拍板，可进入实现**

**现状**
状态栏已有「行数」「编码 + 换行符」「Ln:Col」，**没有**字数统计。

**已定决策**
| # | 决策项 | 结论 |
|:--|:--|:--|
| ① | 显示项 | **只给「字数」一项**，不单独展示「词数」 |
| ② | 计数口径 | **口径 B**：CJK 逐字计数 + 拉丁按词计数，两者相加 |
| ③ | Markdown 语法符号 / 代码块 | **不排除**，按纯文本算 |
| ④ | 更新时机 | **只统计"已保存内容"**（编辑中不实时更新，保存后更新） |
| ⑤ | 适用文件类型 | **只 markdown / txt** |

**期望**
1. 状态栏新增「字数 N」，与现有项同排、风格一致；
2. `N` 的算法严格按口径 B：**CJK 字符逐字计 1，拉丁文按空白分词计 1，两者相加**（例：`你好，hello world` → `2 + 2 = 4`）；
3. 计数**只在加载 / 保存时算一次**，**不得进入渲染路径**（打字时不做整串扫描；编辑中的未保存改动**不计入**字数）；
4. **顺手偿还**现有债务：把状态栏当前在渲染路径里现算的行数计数挪到同一处一次性计算；
5. 仅对 **markdown / txt** 文件显示该项；其它文件类型（代码、图片、二进制、超大）**不显示**，且不产生任何报错；
6. 中英混排文档给出的数字**可解释**（用户能对得上"我写了多少字"）。

**被否决的口径**
| 口径 | 定义 | 结论 |
|:--|:--|:--|
| A（IntelliJ 式） | 空白分词的词数 + 不含空白的字符数 | ❌ 中文语境下"词数"无意义 |
| C（`Intl.Segmenter`） | 语言学分词 | ❌ 实测 2 MiB 文本 **608 ms/次**，不可用 |

**明确不做**
- 不做实时（跟随编辑）字数统计 —— 编辑中的数字不变，保存后才更新；
- 不排除 Markdown 语法符号与代码块 —— 按纯文本统计，不做 markdown 解析；
- 不做"词数"独立展示项；
- 不做"工具 → 字数统计"详细弹窗（段落数 / 纯中文字数 / 纯英文词数等分解）—— 留待后续需求。

**根因提示**：状态栏订阅整个 store 快照，**每次按键 + 每 2 秒一次 git 轮询都会触发重渲染** ⇒ 在渲染路径里做 O(n) 计数会被放大。真实中文文档通常 10 KB–100 KB，代价按比例缩小 20–200 倍；风险不在"计数本身贵"，而在"在每次按键都重渲染的组件里做计数"。本需求采用"加载/保存时算一次"的方案 ⇒ **逐键开销为 0**。
